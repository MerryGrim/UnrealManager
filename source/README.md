# Unreal Manager

Независимый лёгкий менеджер Unreal Engine для Windows: движки, проекты, Vault, плагины, обновления и загрузки без магазина игр.

Скачать [0.9.1 — установщик и portable](https://github.com/MerryGrim/UnrealManager/releases/tag/v0.9.1).
Изменения и границы проверки: [CHANGELOG.md](CHANGELOG.md).

## Возможности 0.9.1

- Tauri + React + TypeScript UI.
- Rust backend.
- Разделы: Главная, Unreal Engine, Проекты, Библиотека, Плагины, Обновления, Загрузки, Настройки.
- Автопоиск установленных UE в типовых каталогах и через Windows Registry.
- Автопоиск `.uproject` в стандартных каталогах пользователя.
- Чтение `EngineAssociation` из `.uproject`.
- Запуск проекта через зарегистрированную Windows ассоциацию `.uproject`.
- Вход Epic, библиотека Fab, локальный Vault и подключение Epic VaultCache.
- Установка, проверка, изменение и удаление движков с выбором компонентов.
- Проверка установленных файлов использует ограниченное число потоков с учётом типа накопителя; показывает доли процента, скорость проверки, прочитанные байты и текущий файл.
- Скачивание и установка ассетов, проектов и плагинов; обновление контента с просмотром конфликтов.
- Пауза, докачка через HTTP Range и продолжение загрузок после перезапуска. Точная версия и действия сохраняются; продолжение запускается пользователем.
- Последовательная очередь скачивания в Vault: одна активная загрузка, изменение порядка ожидающих перетаскиванием или кнопками. После перезапуска сохранённая очередь ждёт явного запуска. Копирование в проект запускается отдельно.
- История загрузок, трей, настройки скорости/хранилища, девять языков интерфейса.
- Категории настроек: Интерфейс, Загрузки, Хранилище, Проекты и Обновления приложения.

## Политика GPU

Лаунчер по умолчанию устанавливает для WebView2:

```text
--disable-gpu --disable-gpu-compositing
```

Цель: сам Unreal Manager не должен активировать дискретную NVIDIA/AMD GPU на гибридных ноутбуках. Интерфейс специально сделан без WebGL, canvas-анимаций, blur/backdrop-filter и постоянных render-loop.

Флаги задаются до создания главного окна и окон Epic. Проверка конфигурации не заменяет измерение GPU на конкретном компьютере; наличие Chromium `gpu-process` само по себе не доказывает аппаратную нагрузку.

> Windows DWM может использовать системный графический адаптер для композиции рабочего стола, но процесс Unreal Manager не должен создавать собственную аппаратно-ускоренную WebView2 GPU workload.

## Обновления программы через GitHub

В «Настройки → Обновления приложения» можно выбрать stable/beta, отключить автоматическую проверку,
проверить версию вручную, скачать и применить обновление. Автоматическая
проверка выполняется один раз при запуске, не чаще раза в сутки. Службы,
задания планировщика и постоянного опроса нет.

Перед применением проверяются подпись манифеста и SHA-256 пакета. Программа
дожидается безопасной остановки операций и сохраняет задачи. Временная копия
того же EXE ждёт завершения исходного процесса, заменяет файлы и запускает
программу. Установленная версия использует Inno Setup с прежним каталогом;
portable заменяет только пять файлов программы, сохраняя Data и portable.marker.
При ошибке применения или отсутствии подтверждения запуска восстанавливается
резервная копия файлов. Прерывание самого Inno Setup может потребовать ручного
восстановления из сохранённой копии; неизвестные изменения не перезаписываются.

Подробности формата, подписи и выпуска: [UPDATES.md](UPDATES.md).
Клиент обновлений появился в beta.7: версии beta.7 и новее могут получить 0.9.1 через приложение.
Стабильный выпуск доступен в обоих каналах обновлений. В beta.7 нажмите
**Settings → Unreal Manager updates → Check for updates**
(названия элементов английского интерфейса).
Beta.6 не содержит клиента обновлений: переход на beta.7 или новее выполняется
обычным установщиком или заменой файлов portable с сохранением Data и portable.marker.
В цикле выпуска 0.9.0 проверены реальные загрузка и докачка ассета после
перезапуска, копирование в отдельный проект, установка и восстановление движка,
запуск Editor, работа очереди и уборка тестовых данных. Результаты относятся к
проверенным операциям и сборкам; тестовые UI-данные не заменяют реальную проверку.
Если общий список Epic защищён правами Windows, установка может завершиться с
предупреждением: наличие движка в Unreal Manager не означает его обнаружение
Epic Launcher. Повторная регистрация с повышением прав пока не реализована.

## Сборка

Для сборки требуются Windows x64, Node.js/npm, Rust stable MSVC, Microsoft C++ Build Tools и Windows SDK. Для работы нужен Microsoft WebView2 Runtime; компиляторы, Node.js и Playwright в приложение не входят. Чистые Windows 10/11 и установка недостающих системных компонентов требуют отдельной проверки. Версии библиотек закреплены lock-файлами.

```powershell
.\BUILD-WINDOWS.ps1 -Configuration both
```

Релизная сборка:

```powershell
.\BUILD-WINDOWS.ps1 -Configuration release -SkipDependencies
```


## Подготовка среды сборки

`BUILD-ENV.ps1` ищет инструменты в `UM_TOOLS_ROOT`, локальной папке `../tools`, общей папке `Tools` рядом с `Projects` и в `PATH`. Скрипт меняет только окружение текущего процесса. Кэши, временные файлы и результаты сборки остаются на томе рабочей папки; их расположение можно задать через переменные окружения. По умолчанию EXE создаются в `src-tauri/target/debug` и `src-tauri/target/release`.

Для Inno-установщика нужен отдельно установленный Inno Setup 7:

Перед сборкой установщика скачайте официальный **Evergreen Bootstrapper**
[Microsoft WebView2](https://developer.microsoft.com/microsoft-edge/webview2/)
в `installer/dependencies/MicrosoftEdgeWebview2Setup.exe`. Этот сторонний EXE
не включён в репозиторий; скрипт проверяет его подпись Microsoft.

```powershell
.\BUILD-INSTALLER.ps1 -SkipBuild
```

Для новой публикации используйте отдельную папку, чтобы сохранить предыдущие
сборки: `-OutputDirectory '..\Releases\0.9.0\my-release'`.
Если установщик с таким именем уже существует, скрипт остановится.

Новые локальные дистрибутивы создаются в `../Releases/0.9.0`. Рядом с portable EXE должен находиться `portable.marker`; данные хранятся в соседней папке `Data`.

## Проверки

```powershell
. .\BUILD-ENV.ps1
cargo test --locked --manifest-path .\src-tauri\Cargo.toml
node ..\verification\run-beta7.cjs
```

Для UI-проверок задайте `UM_PLAYWRIGHT_MODULE` на существующий пакет Playwright. Подробности — `../verification/README.md`. Новые логи и скриншоты сохраняются в `verification/current`, архивные результаты не заменяются. UI-проверки используют тестовые данные и не подтверждают реальную загрузку Fab.
