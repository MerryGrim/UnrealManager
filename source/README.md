# Unreal Manager 0.2.0-beta.6

Независимый лёгкий менеджер Unreal Engine для Windows: движки, проекты, Vault, плагины, обновления и загрузки без магазина игр.

## Возможности beta.6

- Tauri + React + TypeScript UI.
- Rust backend.
- Разделы: Главная, Unreal Engine, Проекты, Библиотека, Плагины, Обновления, Загрузки, Настройки.
- Автопоиск установленных UE в типовых каталогах и через Windows Registry.
- Автопоиск `.uproject` в стандартных каталогах пользователя.
- Чтение `EngineAssociation` из `.uproject`.
- Запуск проекта через зарегистрированную Windows ассоциацию `.uproject`.
- Вход Epic, библиотека Fab, локальный Vault и подключение Epic VaultCache.
- Установка, проверка, изменение и удаление движков с выбором компонентов.
- Скачивание и установка ассетов, проектов и плагинов; обновление контента с просмотром конфликтов.
- Пауза, докачка через HTTP Range и продолжение загрузок после перезапуска. Точная версия и действия сохраняются; продолжение запускается пользователем.
- История загрузок, трей, настройки скорости/хранилища, девять языков интерфейса.

## Политика GPU

Лаунчер по умолчанию устанавливает для WebView2:

```text
--disable-gpu --disable-gpu-compositing
```

Цель: сам Unreal Manager не должен активировать дискретную NVIDIA/AMD GPU на гибридных ноутбуках. Интерфейс специально сделан без WebGL, canvas-анимаций, blur/backdrop-filter и постоянных render-loop.

Флаги задаются до создания главного окна и окон Epic. Проверка конфигурации не заменяет измерение GPU на конкретном компьютере; наличие Chromium `gpu-process` само по себе не доказывает аппаратную нагрузку.

> Windows DWM может использовать системный графический адаптер для композиции рабочего стола, но процесс Unreal Manager не должен создавать собственную аппаратно-ускоренную WebView2 GPU workload.

## Незавершённая работа

Уведомления об обновлении самой программы через GitHub пока находятся в отдельном неподключённом модуле `src-tauri/src/app_updates.rs`. Реальный полный цикл Fab/UE с закрытием и продолжением требует отдельной проверки с аккаунтом и материалами пользователя.

### План автообновлений через GitHub

Статус на 19 октября 2026 года: запланировано, внедрение отложено по просьбе пользователя. Публикация исходников и сайта не включает подключение автообновлений. План относится к Unreal Manager; отдельной серверной части в этом проекте нет. Rust backend входит в тот же EXE и обновляется вместе с интерфейсом.

GitHub Releases выбран источником версий и пакетов. Для размещения информации об обновлениях достаточно Releases API или статического манифеста; отдельный сервер обновлений не требуется. [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [Tauri Updater](https://v2.tauri.app/plugin/updater/).

1. Репозиторий исходников и будущих релизов — [MerryGrim/UnrealManager](https://github.com/MerryGrim/UnrealManager). `MerryGrim/UM` в тестах заготовки остаётся примером; модуль не подключён к реальному источнику. Добавить сборку и публикацию версий, описаний изменений, установщика и portable-пакета; подготовить подписи обновлений.
2. Подключить проверку версий: при запуске не чаще раза в сутки, вручную в «О приложении», с выбором stable/beta и отключением фоновой проверки. Заготовка уже сравнивает SemVer, исключает drafts, ограничивает сетевые запросы и проверяет адреса ссылок. Она пока открывает загрузку в браузере; автоматического применения пакета нет.
3. Добавить уведомление о версии и действии «Обновить». Скачать пакет, проверить подпись, дождаться безопасной остановки активных операций и сохранения задач, затем закрыть приложение, применить обновление и запустить его снова. Настройки, сеанс Epic, Vault, проекты и задачи должны сохраниться.
4. Проработать отдельно установленную и portable-версии. Существующий дистрибутив использует Inno Setup, а стандартные Windows-пакеты Tauri Updater — NSIS/MSI с обязательной подписью. Перед внедрением выбрать механизм применения Inno либо проверить переход на штатный updater; перенос установки должен сохранять путь и идентичность приложения. Portable требует замены файлов после завершения процесса и сохранения `Data`/`portable.marker`. [Форматы и подписи Tauri Updater](https://v2.tauri.app/plugin/updater/).
5. Проверить повреждённый пакет, неверную подпись, обрыв сети, отсутствие обновления, смену канала и откат при ошибке применения. Провести полный цикл на установленной и portable-копиях с сохранёнными задачами; после подключения повторить замер CPU/GPU.

Ограничения реализации: без постоянно работающей службы обновлений и частого опроса; временный помощник допустим только на время замены файлов. Все окна сохраняют программную отрисовку WebView2. Ключи подписи не включаются в приложение; подключение модуля к репозиторию, публикация пакетов автообновлений и их установка сейчас не выполняются.

## Сборка

Для сборки требуются Windows x64, Node.js/npm, Rust stable MSVC, Microsoft C++ Build Tools и Windows SDK. Готовому EXE нужен только системный WebView2 Runtime: компиляторы, Node.js и Playwright в приложение не входят. Версии библиотек закреплены lock-файлами.

```powershell
.\BUILD-WINDOWS.ps1 -Configuration both
```

Релизная сборка:

```powershell
.\BUILD-WINDOWS.ps1 -Configuration release -SkipDependencies
```


## Сборка на этом компьютере

Инструменты находятся в `D:\AI\Tools`, исходники и результаты — на D:. `BUILD-ENV.ps1` поддерживает `UM_TOOLS_ROOT`, локальную папку `../tools` и общую папку `Tools` рядом с `Projects`; меняет только окружение текущего процесса. По умолчанию EXE создаются в `src-tauri/target/debug` и `src-tauri/target/release`.

Для Inno-установщика нужен отдельно установленный Inno Setup 7:

Перед сборкой установщика скачайте официальный **Evergreen Bootstrapper**
[Microsoft WebView2](https://developer.microsoft.com/microsoft-edge/webview2/)
в `installer/dependencies/MicrosoftEdgeWebview2Setup.exe`. Этот сторонний EXE
не включён в репозиторий; скрипт проверяет его подпись Microsoft.

```powershell
.\BUILD-INSTALLER.ps1 -SkipBuild -Compiler 'D:\AI\Tools\InnoSetup7\ISCC.exe'
```

Для новой публикации используйте отдельную папку, чтобы сохранить предыдущие
сборки: `-OutputDirectory '..\Releases\0.2.0-beta.6\my-release'`.
Если установщик с таким именем уже существует, скрипт остановится.

Новые дистрибутивы находятся в `../Releases/0.2.0-beta.6`. Рядом с portable EXE должен находиться `portable.marker`; данные хранятся в соседней папке `Data`.

## Проверки

```powershell
. .\BUILD-ENV.ps1
cargo test --locked --manifest-path .\src-tauri\Cargo.toml
node ..\verification\run-beta6.cjs
```

Для UI-проверок задайте `UM_PLAYWRIGHT_MODULE` на существующий пакет Playwright. Подробности — `../verification/README.md`. Новые логи и скриншоты сохраняются в `verification/current`, архивные результаты не заменяются. UI-проверки используют тестовые данные и не подтверждают реальную загрузку Fab.
